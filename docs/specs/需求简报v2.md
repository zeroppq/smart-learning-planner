# 智学规划 MVP 需求简报（比赛版）

- 版本：v2（按"4 天倒计时"战略裁剪后）
- 日期：2026-11-14
- 比赛截止：2026-11-18
- 状态：需求已确认，进入 OpenSpec 提案阶段
- 用途：华为云比赛参赛项目，第一版以"四天内可交付、核心闭环可演示"为准

---

## 0. 一句话定义

智学规划是一个**面向大学生的"自学掌握度判定系统"**：你说出学习目标，它排出知识点路线和每日任务，每天先抽查旧知识、再带你学新知识，用"讲清楚 → 做对题 → 做出来"三层判定你是不是真会，并把结果画进路线图，据此调整后续计划。

它不是一个讲知识点的 AI 家教，也不是一个刷题工具，而是一个**替你做判断、替你排顺序、替你记结果的学习管家**。

## 1. 目标用户与核心痛点

### 1.1 目标用户

| 项目 | 说明 |
|------|------|
| 是谁 | 在校大学生，有教材 / 课件 / 考试范围，但自学时"看得懂、做不出" |
| 使用方式 | 单人使用，无需注册登录，打开即用 |
| 设备 | 手机浏览器与电脑浏览器都要能正常使用 |
| 数据 | 本地持久保存，关掉再打开还在 |
| 使用节奏 | 默认每天 40 分钟（用户可填参数） |

### 1.2 六个真实痛点与应对

| 编号 | 痛点 | 具体表现 | 本产品怎么应对 | 比赛版是否做 |
|------|------|----------|----------------|--------------|
| P1 | 不知道学什么 | 有课件但不知从哪一章下手 | 一句话目标 → 自动拆有序知识点 | 是 |
| P2 | 不知道怎么学 | 视频看完不知下一步 | 路线图看全局 + 每日 1-3 项任务 | 是 |
| P3 | 学了就忘 | 过两周全忘，感觉白学 | 每天开场抽查，不过关回炉 | 是（演示可手动触发） |
| P4 | 没人指导 | 卡住搜不明白，没人可问 | 基于自己资料的答疑，必须给出处 | 是 |
| P5 | 很难坚持 | 断更两三天就再没打开 | 首页显示"上次停在哪" | 部分（页面内提醒移入以后） |
| P6 | 不知道自己会不会 | 自以为懂，合上书做不出 | 三层判定 + 路线图状态 | 是（薄弱点独立面板移入以后） |

### 1.3 关键定位判断

用户最痛的是**"看懂了但没底"**。缺的不是内容供给，而是**掌握度判定**。因此：

> 凡是不产生"判定结果"的功能，比赛版一律不做。

## 2. 核心闭环

```
[0 资料入库]
   上传 TXT / MD / PDF（PDF 解析不稳定则演示改用 MD/TXT）
        ↓  解析、清洗、切成知识点
   知识点挂回来源资料（溯源 = 文档名 + 段落序号）
        ↓
[1 定目标]
   一句话：学什么 + 多久内 + 为什么（考试 / 项目 / 兴趣）
        ↓  AI 追问 1-3 个问题确认范围、基础、时间
[2 出计划]（规划师）
   知识点路线图（含前置依赖）+ 每日任务（1-3 项，标注预计用时）
        ↓
[3 每日学习]（督学）
   开场抽查（1/3/7 天规则，可手动触发）→ 带学 → 三层判定
        ↓
[4 记结果]
   每个知识点记：三层结果、卡点、用时
        ↓
[5 看进度]
   路线图着色（未学 / 学习中 / 已过 / 待回炉）+ 掌握度 + 连续学习天数
        ↓
[6 调计划]
   小调自动（顺延 / 回炉）
   大调 = 页面确认框：规划师给方案，用户点"确认"后生效
        ↓
   回到 [3]
```

### 2.1 三类目标的差异配置

| 场景 | 追问什么 | 计划差异 | 三层判定差异 |
|------|----------|----------|--------------|
| 专业核心知识 | 现有基础、目标深度 | 前置依赖严格 | 三层权重均衡，第三层必须落到应用 |
| 考试与课程知识 | 考试日期、范围、题型 | 按考点优先级排序 | 第二层题量加大，贴合真题风格 |
| 实践与应用知识 | 最终想做出什么 | 以"做出来"倒推知识点 | 第三层权重最高 |

### 3.2 移入"以后再说"（P1）

| 功能 | 移后原因 |
|------|----------|
| 薄弱点独立面板 | 路线图着色已能表达"哪些没过"，独立面板收益低 |

## 4. 两个 AI 智能体职责分工

### 4.1 规划师 Planner

| 项目 | 内容 |
|------|------|
| 一句话职责 | 负责"学什么、按什么顺序学、每天学多少"，并对计划负责 |
| 触发时机 | 新建目标；用户要求重新规划；督学上报"连续不过关 / 进度严重落后" |
| 输入 | 学习目标、每日可用时间（默认 40 分钟）、知识点清单与依赖、历史掌握度、计划执行情况 |
| 输出 | 知识点路线图（含前置依赖）、每日任务、调整方案 |
| 必须做 | 先确认目标边界再出计划；标注知识点来源；给出每日任务预计用时 |
| 不能做 | 不能判定某个知识点是否学会；不能不经用户确认就改动阶段级计划 |
| 产出字段 | `plan_id`、`plan_version`、`knowledge_point_id`、`prerequisite_point_id`、`daily_task_id`、`adjustment_proposal_id` |

### 4.2 督学 Coach

| 项目 | 内容 |
|------|------|
| 一句话职责 | 负责"今天把你按在桌前学完，并说实话你有没有学会" |
| 触发时机 | 进入今日学习页；答完一个问题；用户主动提问 |
| 输入 | 今日任务、知识点与原文、历史判定结果、上次学习停在哪 |
| 输出 | 抽查评价、讲解、三层判定结论、卡点记录、交接数据 |
| 必须做 | 每层判定说明"为什么过 / 不过"；引用资料给出处；失败指出具体卡点 |
| 不能做 | 不能跳过前置依赖；不能为讨好用户放宽标准；不能自己改计划 |
| 产出字段 | `mastery_status`、`mastery_layer_result`、`weak_point_flag`、`review_due_at`、`study_session_id` |

### 4.3 交接协议

| 数据项 | 含义 | 谁写 | 谁读 |
|--------|------|------|------|
| `learning_goal_id` | 学习目标编号 | 系统 | 双方 |
| `plan_id` / `plan_version` | 计划编号与版本 | 规划师 | 督学 |
| `knowledge_point_id` | 知识点编号 | 规划师 | 督学 |
| `prerequisite_point_id` | 前置知识点编号 | 规划师 | 督学 |
| `mastery_status` | not_started / learning / passed / needs_review | 督学 | 双方 |
| `mastery_layer_result` | explain / practice / apply 各自的 pass / fail / partial | 督学 | 规划师 |
| `weak_point_flag` | 是否薄弱点 | 督学 | 规划师 |
| `adjustment_proposal_id` | 调整方案编号 | 规划师 | 用户 |
| `review_due_at` | 下次该复习的时间 | 督学 | 规划师 |

### 4.4 已决定：两个智能体独立构建

不是一个 AI 换提示词，理由：工具集不同、记忆范围不同、可审计、直接对应"多 Agent 协同"得分点。

## 6. 比赛五个评分维度怎么满足

| 维度 | 分值 | 拿分点 | 演示证据 |
|------|------|--------|----------|
| 功能完备度 | 35 | 资料入库 → 定目标 → 出计划 → 每日学习 → 三层判定 → 进度可视化 → 计划调整，七环节闭环 | 一条 3 分钟主线走完不断链 |
| Agent 智能水平 | 20 | 双智能体独立构建与交接；三层递进判定；知识库检索增强；进度驱动调整；历史卡点记忆 | 演示"督学判不过 → 规划师改计划 → 用户确认" |
| 场景应用价值 | 20 | 真实痛点"假懂"；人群明确；效果可用三层过关率衡量 | 真实讲义演示，展示"自以为懂"被识别 |
| 码道使用深度 | 15 | 需求、提案、设计、编码、验证全流程在码道完成 | 过程记录与产物截图 |
| 创意与材料规范 | 10 | "三层判定"记忆点；双智能体交接协议 | 材料结构统一、图示清晰 |

### 6.1 全链路覆盖

| 全链路环节 | 比赛版对应 |
|------------|------------|
| 数据 / 知识库管理 | 上传、解析、知识点切分、溯源关联、预置课程 |
| 数据处理 | 文档解析、清洗、知识点抽取、向量化入库 |
| 模型 / 智能体构建 | 规划师、督学两个独立智能体 + 交接字段 |
| 推理部署 | 网页服务化部署，手机与电脑浏览器可访问 |
| 结果可视化 | 路线图着色、总进度、连续学习天数、调整确认 |

## 7. 重要决定

### 7.1 产品决定（9 条，全部维持）

| 编号 | 决定 | 理由 |
|------|------|------|
| D1 | 一套流程通吃专业课、考试、实践 | 同一条流水线，只是参数不同 |
| D2 | 三层递进判定是否学会 | 直击"看懂了但没底"，也是最大差异点 |
| D3 | 知识库上传为主 + 预置兜底 | 贴合真实资料在手，同时保证演示不空转 |
| D4 | 计划做成"路线图 + 每日任务"两层 | 上层解决"不知学什么"，下层解决"不知怎么学" |
| D5 | 小调自动、大调需用户确认 | 有主动性但不会乱改 |
| D6 | 督学 = 开场抽查 + 陪学 + 记录 | 治遗忘、治没人指导，并给规划师供数据 |
| D7 | 演示主线"上传 → 目标 → 学一点 → 看进度 → 调整" | 一条线覆盖全部五环节 |
| D8 | 不做注册登录等非得分项 | 集中精力在得分项 |
| D9 | 坚持窄而深 | 明确反对四种退化形态 |

### 7.2 比赛版裁剪决定（11 条）

| 编号 | 决定 | 理由 | 代价 |
|------|------|------|------|
| C1 | 只保留 15 项 P0，其余全部移出 | 4 天倒计时，必须保闭环 | 功能列表变短 |
| C2 | "做出来"简化为提交文字/答案 + AI 按标准评阅 | 无需做代码沙箱或自动评测 | 动手感弱于真实环境 |
| C3 | 大调降级为页面确认框 | 不做提案工作流与版本对比 | 无"提案历史"可展示 |
| C4 | 溯源降为"文档名 + 段落序号" | 不解析 PDF 页码布局 | 无法精确到页码 |
| C5 | 预置课程只做 1 门《大学计算机基础》 | 准备 1 门即可撑起演示 | 覆盖面窄 |
| C6 | 上传格式只支持 TXT / MD / PDF | PPTX / DOCX 解析 ROI 低 | 用户需先转换格式 |
| C7 | 不做薄弱点独立面板 | 路线图着色已够表达 | 分析深度下降 |
| C8 | 不做资料删除与页面内提醒 | 非得分点 | 体验略糙 |
| C9 | 只保留"连续学习天数"一个激励数字 | 避免积分徽章开发 | 激励手段单一 |
| C10 | 抽查 1/3/7 天规则 + 手动触发 | 演示时不能等三天 | 需额外做一个触发按钮 |
| C11 | 每日 40 分钟做成可填参数，周期默认 14 天 | 参数化成本低，演示只走前 2-3 天 | 无 |

## 8. 非目标与反目标

### 8.1 非目标

不做通用学习平台、教师端、题库市场、课程商城、多端 App、付费运营。

### 8.2 反目标（做成了就算失败）

| 编号 | 反目标 | 自检方法 |
|------|--------|----------|
| A1 | 只会聊天的问答机器人 | 用户不提问时系统是否仍推进学习 |
| A2 | 打卡 / 待办工具 | 除打勾外 AI 是否真在判定和调整 |
| A3 | 刷题软件 | 是否强制走完"讲清楚"和"做出来" |
| A4 | 功能堆砌、样样都浅 | 每个 P0 能否说出"AI 在这里判断了什么" |

## 10. 风险与预案

| 风险 | 影响 | 预案 |
|------|------|------|
| PDF 解析不稳定 | 演示资料切不出知识点 | 演示资料改用 MD / TXT；PDF 标记为"支持中"，不阻塞主线 |
| 三层判定太耗时 | 闭环走不完 | 单点三层合并在一屏，每层 2-3 轮对话 |
| AI 判定标准飘忽 | 用户不信任 | 判定前固定并展示"过关标准" |

# Spec Delta

## MODIFIED Requirements

### Requirement: 三层判定之讲清楚

督学 MUST 要求用户用自己的话复述知识点，第一层的判定标准 MUST 与题面要求一一对应（说清是什么、解决什么问题、举一个例子），讲不清楚 MUST 判定为未通过。"与本章其他概念的关系" MUST NOT 作为第一层的判定标准或缺口，只能作为讲解或建议内容展示。

#### Scenario: 复述清楚

- **WHEN** 用户用自己的话说明概念是什么、解决什么问题并举出例子，但没有提及它与本章其他概念的关系
- **THEN** 督学判定"讲清楚"通过，进入"做对题"；"与本章的关系"作为建议展示，不影响结论

#### Scenario: 复述含糊

- **WHEN** 用户只是重复原文、缺少题面三要素中的任一项或答不出追问
- **THEN** 督学判定"讲清楚"未通过，指出缺口并要求重新复述

### Requirement: 判定标准前置展示

督学 MUST 在开始三层判定前展示本知识点的过关标准，判定过程中 MUST NOT 擅自降低标准；判定 MUST 只依据当前层前置展示的标准，标准外的内容（包括讲解细节与其他层要求）MUST NOT 作为不通过理由，只能作为建议；缺口清单 MUST 逐条对应本层标准。

#### Scenario: 开始判定前

- **WHEN** 用户进入某个知识点的判定环节
- **THEN** 系统展示该知识点三层的过关标准

#### Scenario: 用户求放宽

- **WHEN** 用户表示"差不多就行"
- **THEN** 督学不降低标准，并说明未通过的具体原因

#### Scenario: 标准外内容不作为不通过理由

- **WHEN** 用户的回答覆盖了当前层全部标准，但缺少标准之外的内容（例如讲解中补充的机制细节）
- **THEN** 督学判定通过，标准外内容只能出现在建议里，不得出现在缺口清单中

### Requirement: 重判一次

系统 MUST 允许用户对未通过结论申请重新判定一次，重判结论 MUST 为最终结果；申请重判 MUST NOT 要求用户重新填写回答，重判基于上一次提交的回答与补充说明进行；重判次数 MUST 在全部参数校验通过且重判完成后才扣除，校验失败或判定服务失败 MUST NOT 消耗重判机会。

#### Scenario: 申请重判

- **WHEN** 用户在判定未通过后填写补充说明并点击"申请重判"
- **THEN** 系统基于上一次提交的回答与补充说明重新判定，反馈就地显示在重判区块内，并明确告知本次为重判最终结果

#### Scenario: 重复申请

- **WHEN** 用户在同一知识点第二次申请重判
- **THEN** 系统拒绝并提示"该知识点重判机会已用完"

#### Scenario: 无效重判不扣次数

- **WHEN** 重判请求因补充说明过短、回答缺失或判定服务失败而未完成
- **THEN** 系统就地提示失败原因，该知识点的重判机会保持未使用

#### Scenario: 重判进行中

- **WHEN** 用户点击"申请重判"后请求尚未返回
- **THEN** 按钮显示进行中状态且不可重复点击，页面有可观察的反馈

## ADDED Requirements

### Requirement: 判定反馈结构化展示

判定结果 MUST 以"结论徽章 + 达标项清单 + 缺口清单"的结构展示，缺口条目 MUST 高亮标识。

#### Scenario: 判定未通过

- **WHEN** 判定结论为未通过或部分通过
- **THEN** 页面显示结论徽章、已达标项清单与缺口清单，缺口条目高亮

#### Scenario: 判定通过

- **WHEN** 判定结论为通过
- **THEN** 页面显示结论徽章与达标项清单，不显示缺口区

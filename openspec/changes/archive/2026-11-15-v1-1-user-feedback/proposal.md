# Proposal

## Why

三位真实用户试用后反馈了 3 条功能缺陷，诊断报告（`docs/diagnosis-v1.1.md`）已逐一复现并定位根因：符合第一层题面要求的回答被判"部分通过"（判定依据越界）、申请重判按钮点击无反应（前端静默失败 + 后端先扣次数）、修改每日时间后计划排期完全不变且旧计划从页面消失（目标替换而非更新）。缺陷均已拍板修复方向（Q1 选 C、Q2 选 B、Q3 选 A），同时纳入两条试用中提出的体验优化（知识点可读性、判定反馈结构化）与一次视觉收尾。比赛版已于 2026-11-15 冻结（v1.0.1），本次为赛后 v1.1 迭代。

## What Changes

- **缺陷A（判定依据越界，Q2 选 B）**：第一层"讲清楚"的标准清单与题面三要素一一对应（是什么 / 解决什么问题 / 举例）；"与本章其他概念的关系"从第一层标准和缺口清单中移除，降为讲解或建议区内容；判定提示词增加硬约束"只依据本层前置展示标准判定，标准外内容只能作为建议、不得作为不通过理由"；判定结果校验增加"缺口必须对应本层标准"的过滤。
- **缺陷B（重判按钮无反应，Q3 选 A）**：前端修复判定后答案被清空导致的静默失败，提示就地显示在重判区块内，按钮增加进行中状态；后端重判次数扣除移到全部参数校验通过之后，与模型调用放在同一事务边界，校验失败或模型调用失败不扣次数（返还）。
- **缺陷C（改时间计划链路，Q1 选 C）**：修改每日时长改为更新当前目标（同一目标、同一版本线，不再归档重建）；计划版本不许回退；排期算法让时长参与"每天几项"的推导（具体规则与 40 / 50 / 60 分钟三档边界示例见 design.md，提案审查时确认）；改时长后展示前后对比确认（复用计划大调的交互模式）；页面明示"任务条数由知识点数量与学习周期决定"。
- **体验优化 #2（知识点可读性）**：讲解与答疑中的来源引用改为角标 / 折叠展示（保留溯源能力，不逐段刷屏）；知识点列表卡片化（标题 + 摘要 + 展开）。
- **体验优化 #5（判定反馈结构化）**：判定结果改为"结论徽章 + 达标项清单 + 缺口清单"的结构化展示，缺口高亮。
- **收尾 #1（视觉打磨，最后一组）**：排版层次、间距、重点突出，不大改版。
- **流程改进**：每个缺陷修复的回归用例必须包含页面点击路径（浏览器自动化或端到端脚本），不得只有接口脚本——缺陷 B 正是纯接口验证漏掉的。

### 不做的事（Out of Scope）

- 不做多目标并行、目标归档确认弹窗（改时长走更新，不触发归档）。
- 不做向量检索、艾宾浩斯间隔升级、资料删除、学习报告导出等 `docs/backlog.md` 其余条目。
- 不修"计划生成偶发整单失败"（模型引用不存在的知识点 ID，诊断报告 5.1 已记录）：属模型输出稳定性问题，本次只观察不处理。
- 不改督学可写数据范围（仍限 `mastery_record` / `study_session`）。
- 不改模型配置方式（仍走环境变量），不更换模型。
- 不删除来源标注能力（仅改展示形态）。
- 不做设置页、登录、移动 App 等比赛期已裁剪项。
- 不改知识库解析与切分逻辑。

## Capabilities

### New Capabilities

无。本次全部是对既有能力的修改。

### Modified Capabilities

- `learning-session`: 第一层判定标准与题面对齐、判定只依据本层标准、缺口白名单校验（缺陷A）；重判的页面交互与次数扣除语义（缺陷B）；判定反馈结构化展示（#5）。
- `learning-plan`: 修改每日时长改为更新当前目标且版本不回退、时长参与每日任务数量推导、改时长前后对比确认、任务条数决定因素明示（缺陷C）。
- `knowledge-base`: 来源引用的展示形态改为角标 / 折叠、知识点列表卡片化（#2）。

## Impact

- **代码**：`src/lib/agents/coach/`（standard.ts、system-prompt.ts、service.ts）、`src/app/api/coach/judge/route.ts`、`src/app/page.tsx`（今日学习页）、`src/app/api/goals/route.ts`、`src/lib/plans/repository.ts`、`src/lib/agents/planner/schema.ts`、`src/app/plan/page.tsx`、`src/app/knowledge/page.tsx`；视觉打磨涉及四个页面但不改接口。
- **数据**：`learning_goal` 的更新语义变化（改时长不再产生新目标记录）；无表结构破坏性变更，详见 design.md 的 schema 影响分析。
- **回归底线**：现有 79 项测试用例只增不减；热修 C-4 的行为（旧 goalId 不再 409）不得回退。
- **流程**：缺陷修复的验收必须包含页面点击路径回归（写入 tasks.md）。
- **工作量**：控制在 3-4 天；超出时裁剪 #1 视觉打磨的范围，不加时间。

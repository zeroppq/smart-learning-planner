# Design

> 说明：本文中的技术选型是**推荐方案**，需要用户审查确认；确认后 `tasks.md` 按此编排。若用户改选其他方案，任务顺序不变，只替换对应实现步骤。

## Context

项目为全新空仓库，无既有代码与技术约束。产品背景与动机见 `proposal.md` 的 Why 一节，能力要求见 `specs/` 下五份规格。

真正影响设计的约束只有四条：

1. **只剩 4 天**（截止 2026-11-18），技术方案必须以"少调试、少依赖、能演示"为第一优先。
2. **单人使用、无账号**，但数据必须持久化，刷新和重启后还在。
3. **必须覆盖 AI 应用全链路**：知识库管理、数据处理、智能体构建、推理部署、结果可视化。
4. **产品负责人无编程基础**，方案要能被非技术人员理解，且失败时要有兜底。

## Goals / Non-Goals

**Goals:**

- 用一套统一技术栈同时完成前端页面、后端接口、智能体调用与部署，减少跨栈调试。
- 让"知识库 → 计划 → 学习 → 判定 → 可视化 → 调整"这条链路在 3 分钟内可完整演示。
- 所有 AI 输出都能指回资料来源，且模型调用失败时不破坏学习状态。
- 数据模型围绕"知识点 + 掌握状态"组织，为后续扩展留出字段。

**Non-Goals:**

- 不做高并发、多租户、权限体系。
- 不做向量数据库集群、模型微调、自建推理集群。
- 不做前端设计系统与复杂动效。
- 不做移动 App 与离线同步。

## Decisions

### 决策总览

| 编号 | 决策点 | 推荐方案 | 主要备选 | 选择理由（大白话） |
|------|--------|----------|----------|--------------------|
| D1 | 应用形态 | Next.js 一体化（React 页面 + 同仓接口） | 纯前端 + 独立后端；Vue + FastAPI | 一套代码同时管页面和接口，少一个工程、少一次联调 |
| D2 | 数据存储 | SQLite 文件数据库（服务端读写） | 浏览器 localStorage；云数据库 | 单用户场景够用，零配置，数据就是一个文件，备份和演示都简单。实际落地采用 Node 24 内置 `node:sqlite` 替代 `better-sqlite3`，原因是避免 Windows 原生编译失败；"单文件 SQLite"的实质不变 |
| D3 | 模型接入 | 华为云 ModelArts Studio 的对话模型 API（具体模型与端点以账号开通结果为准） | 其他兼容 OpenAI 协议的服务；本地模型 | 比赛是华为云赛道，用云上模型能体现"推理部署"；接口协议通用，换供应商成本低 |
| D4 | 知识库检索 | 关键词 + 章节结构打分检索（BM25 思路），预留向量检索接口 | 直接全文塞进提示词；向量数据库 | 4 天内向量化调试风险高；评分看的是"回答有出处"，结构化检索已够 |
| D5 | 文档解析 | TXT / MD 直接读；PDF 用 Node 端解析库抽取文本 | 调云端文档解析服务；只支持纯文本 | 格式少、可控；解析失败可降级，不阻塞演示 |
| D6 | 双智能体 | 两个独立模块：独立系统提示、独立工具集、独立状态读写范围 | 一个模型两套提示词来回切 | 独立模块才能说清"谁在干什么"，也才对应"多 Agent 协同"得分点 |
| D7 | 部署 | 华为云 ECS 上以 Node 进程运行，前置反向代理 | 容器服务 CCE；静态托管 | 单进程部署最快，出问题好排查；仍属于云上部署 |
| D8 | 前端结构 | 5 个主页面 + 移动端响应式布局 | 单页折叠式；多页传统站点 | 页面数量与闭环环节一一对应，评审看得懂 |
| D9 | 状态管理 | 以知识点状态机为核心，页面只读状态、不各存一份 | 每个页面各自维护状态 | 避免"路线图显示已过、学习页说没过"这类不一致 |

### D1 应用形态：Next.js 一体化

- **推荐**：Next.js（App Router）+ TypeScript。页面与接口在同一仓库，接口用 Route Handler 实现。
- **备选 A**：Vue 3 + Vite 前端，另起一个 Python FastAPI 后端。优点是前后端职责清楚；缺点是要维护两个工程、两套依赖、两次部署。
- **备选 B**：纯静态页面 + 浏览器直接调模型接口。优点是极简；缺点是 API Key 暴露在前端，且无法做服务端检索。

推荐理由：4 天工期下，"少一个工程"比"架构更标准"更值钱。

### D2 数据存储：SQLite

- **推荐**：SQLite 单文件数据库，服务端通过 `better-sqlite3` 读写。
- **备选 A**：浏览器 `localStorage` / `IndexedDB`。优点是零后端；缺点是不同浏览器各存一份、无法服务端检索、演示换设备就没了。
- **备选 B**：华为云 RDS。优点是正规；缺点是开通、白名单、连接池都要时间，收益与成本不匹配。

推荐理由：单用户 + 数据量小 + 需要服务端检索，SQLite 正好卡在中间。

### D3 模型接入：华为云 ModelArts Studio

- **推荐**：调用华为云 ModelArts Studio 提供的对话模型接口，走 OpenAI 兼容协议。
- **备选 A**：其他兼容 OpenAI 协议的服务。优点是切换成本低；缺点是比赛材料里"华为云"的体现会弱。
- **备选 B**：本地部署开源模型。优点是完全可控；缺点是显存、部署、推理速度都是 4 天内的高风险项。

统一封装一层 `model-client`：所有智能体都通过它调用，换供应商只改一个文件。这是"预留扩展机制"的落点。

### D4 知识库检索：结构化关键词检索优先

- **推荐**：按"课程 → 章节 → 段落"建索引，检索时先按知识点定位章节，再在章节内用关键词打分取前 N 段，拼进提示词。
- **备选**：向量检索（embedding + 相似度）。优点是语义召回好；缺点是要额外跑 embedding、存向量、调阈值，4 天内属于"高投入、低可见收益"。
- **预留**：`retriever` 接口按"输入问题 → 返回段落列表"定义，后续可替换为向量实现，不影响上层。

### D5 文档解析

| 格式 | 方案 | 失败表现 |
|------|------|----------|
| TXT | 直接读文本 | 编码异常时提示另存为 UTF-8 |
| MD | 直接读文本，按标题切章节 | 无标题时按空行切段 |
| PDF | Node 端解析库抽取文本 | 抽取字数过少则标记"解析失败"，提示改用 MD/TXT |

### D6 双智能体落地

| 项目 | 规划师 Planner | 督学 Coach |
|------|----------------|------------|
| 代码位置 | 独立模块 `planner` | 独立模块 `coach` |
| 系统提示 | 只负责目标澄清、路线、任务、调整 | 只负责抽查、讲解、判分、记录 |
| 工具集 | 读知识点、读掌握度、写计划、写任务、写调整方案 | 读知识点与原文、读判定标准、写判定结果、写复习时间 |
| 可写数据 | `plan`、`daily_task`、`adjustment_proposal` | `mastery_record`、`study_session` |
| 不可写数据 | 不得写 `mastery_record` | 不得写 `plan`、`daily_task` |
| 交接方式 | 写 `plan_id`、`plan_version` 供督学读取 | 写 `mastery_status`、`weak_point_flag`、`review_due_at` 供规划师读取 |

两个模块共用一个 `model-client` 与一个 `retriever`，但提示词、工具白名单、可写表范围完全分开。

### D7 部署

- 华为云 ECS（云服务器）上运行 Node 进程，前置 Nginx 反向代理，暴露 80/443。
- 环境变量管理模型端点与密钥，密钥不进仓库。
- 备选 CCE 容器部署：更"云原生"，但会多出镜像构建与编排时间，4 天内不划算。

### D8 页面结构

| 页面 | 对应闭环环节 | 主要内容 |
|------|--------------|----------|
| 首页 / 今日学习 | 抽查 → 带学 → 三层判定 | 上次停留、今日任务、督学对话区 |
| 知识库 | 资料入库 | 上传、资料列表、解析状态、知识点与溯源 |
| 学习计划 | 定目标 → 出计划 | 目标输入与追问、路线图、每日任务 |
| 进度 | 看进度 → 调整 | 路线图着色、总进度、待回炉、连续天数、调整确认框 |
| 设置 | 参数 | 每日时长、重判、数据导出（可后置） |

### D9 数据模型

| 表 | 关键字段 | 说明 |
|----|----------|------|
| `learning_goal` | `learning_goal_id`、`goal_text`、`daily_minutes`、`target_date`、`goal_status` | 单目标约束：同时只有一条 `active` |
| `source_material` | `source_material_id`、`material_name`、`material_format`、`parse_status` | `parse_status` 取 processing / success / failed |
| `knowledge_point` | `knowledge_point_id`、`source_material_id`、`point_title`、`chapter_name`、`paragraph_index`、`knowledge_point_order` | `paragraph_index` 即溯源用的段落序号 |
| `plan` | `plan_id`、`learning_goal_id`、`plan_version`、`plan_status` | 版本号用于"大调确认后生效" |
| `daily_task` | `daily_task_id`、`plan_id`、`knowledge_point_id`、`task_date`、`estimated_minutes`、`task_status` | 顺延即改 `task_date` |
| `mastery_record` | `mastery_record_id`、`knowledge_point_id`、`mastery_status`、`explain_result`、`practice_result`、`apply_result`、`review_due_at`、`weak_point_flag` | 三层结果各存 pass / fail / partial |
| `study_session` | `study_session_id`、`knowledge_point_id`、`study_started_at`、`study_ended_at` | 记录单次学习 |
| `adjustment_proposal` | `adjustment_proposal_id`、`plan_id`、`proposal_reason`、`proposal_content`、`proposal_status` | `proposal_status` 取 pending / accepted / rejected |

字段命名规则：统一小写下划线语义化长名，公共字段（`created_at`、`updated_at`）全局一致。

## Risks / Trade-offs

| 风险 | 影响 | 应对 |
|------|------|------|
| PDF 解析不稳定 | 知识点切不出来，演示断链 | 演示资料固定用 MD/TXT；PDF 标注"支持中"；解析失败只影响单份资料 |
| 模型响应慢或超时 | 学习页卡住 | 流式输出 + 单次超时兜底 + 重试一次 |
| 4 天工期压缩 | 功能做不完 | 严格按 P0 清单，任何新增需求一律进 P1；11.18 不排开发任务 |
| SQLite 并发写 | 多请求同时写导致锁 | 单用户场景串行写入，写操作统一走一个队列 |
| 智能体判定不一致 | 同一答案两次结果不同 | 判定前固定并展示过关标准；重判只允许一次 |
| 云上模型未开通 | 无法调用 | 模型客户端支持切换端点；演示前完成连通性验证 |
| 换技术栈 | tasks 需重排 | 决策表列出备选方案，替换只影响对应步骤 |

## Migration Plan

全新项目，无历史数据迁移。

1. 初始化工程与依赖，确认本地可启动。
2. 建库建表，导入预置课程与讲义。
3. 按"知识库 → 计划 → 学习 → 可视化 → 协同"顺序联调。
4. 部署到 ECS，验证手机与电脑浏览器均可访问。
5. 回滚策略：保留上一版构建产物与数据库文件副本，异常时直接替换回退。

# Proposal

## Why

大学生自学时最常见的卡点不是"找不到资料"，而是**"看懂了但没底"**：视频看完、例题看懂，合上书却做不出来，也不知道自己到底算不算学会。现有 AI 学习工具大多停留在"生成讲解"或"刷题"，没有人真正替学生判定掌握程度、安排学习顺序、并根据进度调整计划。

本项目要在 4 天内（截止 2026-11-18）交付一个可演示的比赛版 MVP，用一条完整闭环回答这个问题：**说目标 → 出计划 → 按计划学 → 判定会不会 → 看进度 → 调整计划**。

## What Changes

- 新建一个网页系统"智学规划"，手机与电脑浏览器均可使用，单人使用、无需注册登录，数据持久化在本地。
- 新增知识库能力：支持上传 TXT / MD / PDF，解析并切成知识点，知识点可溯源到"文档名 + 段落序号"；内置 1 门预置课程《大学计算机基础》作为演示兜底。
- 新增学习目标与计划能力：用户一句话说目标，AI 追问确认范围与时间，生成知识点路线图（含前置依赖）和每日任务（1-3 项），默认每天 40 分钟、周期 14 天。
- 新增每日学习与判定能力：开场抽查旧知识（1/3/7 天，可手动触发），带学新知识，用"讲清楚 → 做对题 → 做出来"三层判定是否真会；"做出来"以用户提交文字/答案、AI 按标准评阅的方式实现。
- 新增基于知识库的答疑：回答必须引用用户资料并给出处。
- 新增进度可视化：路线图着色（未学 / 学习中 / 已过 / 待回炉）、总进度、连续学习天数。
- 新增计划调整：小调自动执行（顺延 / 回炉），大调以页面确认框呈现方案、用户确认后生效。
- 新增双智能体：规划师与督学**独立构建**，通过约定字段交接；规划师管"学什么、什么顺序、每天多少"，督学管"今天学完并判定会不会"。

### 不做的事（Out of Scope）

- 不做注册登录、多用户、权限体系、云同步。
- 不做 PPTX / DOCX 解析，不做 PDF 页码级定位（溯源只到段落）。
- 不做资料删除管理、薄弱点独立面板、页面内提醒 / 断更提醒。
- 不做预置第 2、3 门课程；只做 1 门。
- 不做考纲导入、整套模拟测、错题本、学习报告导出、多目标并行。
- 不做积分、徽章、社交、排行榜、教师端、班级管理。
- 不做移动 App、小程序、语音输入、消息推送。
- 不做代码沙箱或自动判题（"做出来"由 AI 按标准评阅文字答案）。
- 不做支付与运营功能。

## Capabilities

### New Capabilities

- `knowledge-base`: 资料上传、解析与知识点切分、知识点溯源（文档名 + 段落序号）、预置课程包、资料与知识点的双向关联。
- `learning-plan`: 学习目标输入与澄清追问、知识点路线图（含前置依赖）、每日任务、计划调整（小调自动 / 大调确认）。
- `learning-session`: 今日学习页、开场抽查、带学、三层判定（讲清楚 / 做对题 / 做出来）、基于知识库的答疑、学习记录与掌握状态。
- `progress-visualization`: 路线图着色、总进度、连续学习天数与当前停留位置。
- `agent-collaboration`: 规划师与督学的职责边界、独立构建方式、交接字段与触发时机。

### Modified Capabilities

无。项目当前没有既有能力规格。

## Impact

- 代码：全新项目，无既有代码受影响。
- 数据：所有数据保存在本地浏览器；不引入账号与云端存储。
- 外部依赖：需要一个可调用的大模型能力与一个本地持久化方案；具体技术选型在 `design.md` 中比较后确定。
- 演示依赖：预置课程与配套可公开讲义必须在开发期准备好，否则现场演示无内容可跑。
- 风险：PDF 解析可能不稳定，演示资料改用 MD / TXT，PDF 标注"支持中"，不阻塞主线。

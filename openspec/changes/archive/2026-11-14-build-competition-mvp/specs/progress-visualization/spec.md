# Spec Delta

## Purpose

让学生一眼看清"我学到哪、哪些真过了、哪些还没过"，并把这种看得见的状态作为坚持学习的依据；同时也让评审能直观看到学习闭环产生的效果。

## ADDED Requirements

### Requirement: 路线图着色

系统 MUST 在路线图中用颜色区分 not_started、learning、passed、needs_review 四种状态，且 MUST 提供图例说明每种颜色含义。

#### Scenario: 查看路线图

- **WHEN** 用户打开进度页面
- **THEN** 系统按知识点状态着色，并在页面上显示四种状态的图例

#### Scenario: 状态变化后刷新

- **WHEN** 某个知识点判定完成
- **THEN** 路线图中该节点颜色随之更新，无需用户手动刷新

### Requirement: 总进度展示

系统 MUST 展示整体进度，用"已通过知识点数 / 总知识点数"表示，并 MUST 同时展示待回炉数量。

#### Scenario: 查看总进度

- **WHEN** 用户打开进度页面
- **THEN** 系统显示已通过数、总数、待回炉数三个数字

### Requirement: 上次停留位置

系统 MUST 在首页展示"上次学到的知识点"与"上次学习时间"，帮助断更后快速接上。

#### Scenario: 断更后回来

- **WHEN** 用户隔了多天再次打开系统
- **THEN** 首页第一屏显示上次停留的知识点与建议的下一步动作

### Requirement: 连续学习天数

系统 MUST 展示"连续学习天数"这一项数字指标，且 MUST NOT 提供积分、徽章等额外激励。

#### Scenario: 连续学习

- **WHEN** 用户连续多天完成至少一项任务
- **THEN** 系统把连续学习天数累加并展示

#### Scenario: 中断一天

- **WHEN** 用户某天未完成任何任务
- **THEN** 系统把连续学习天数重置为 0，不出现额外惩罚提示

### Requirement: 调整方案可见与可确认

系统 MUST 在大调确认框中展示调整原因、变更前后对比，并提供"确认调整"与"暂不调整"两个操作。

#### Scenario: 展示调整方案

- **WHEN** 规划师提出大调整
- **THEN** 系统展示调整原因、受影响的知识点与变更前后的每日任务对比

#### Scenario: 确认后生效

- **WHEN** 用户点击"确认调整"
- **THEN** 系统应用新计划并刷新路线图与今日任务

# Spec Delta

## Purpose

把学生一句模糊的"我想学某门课"变成可执行的学习路径：先用追问确认边界，再生成带前后顺序的知识点路线图和每日任务，并允许计划随进度调整。

## ADDED Requirements

### Requirement: 学习目标输入

系统 MUST 允许用户用一句自然语言描述学习目标，且 MUST 支持用户补充每天可用时长。

#### Scenario: 提交学习目标

- **WHEN** 用户输入"我想在三周内学懂大学计算机基础，为期末考试做准备"
- **THEN** 系统记录该目标，并把每天可用时长默认设为 40 分钟

#### Scenario: 修改每日时长

- **WHEN** 用户在目标设置中把每天可用时长改为 60 分钟
- **THEN** 系统保存该参数，并在后续生成每日任务时使用新值

### Requirement: 目标澄清追问

规划师 MUST 在生成计划前最多提出 3 个澄清问题，用于确认学习范围、现有基础和时间约束。

#### Scenario: 目标信息不足

- **WHEN** 用户只输入"我想学计算机基础"
- **THEN** 规划师提出不超过 3 个问题，例如范围是否包含某章节、当前基础、希望的完成时间

#### Scenario: 用户跳过追问

- **WHEN** 用户选择"先按默认来"
- **THEN** 规划师按资料覆盖范围与默认 14 天周期直接生成计划，并在计划中标明所采用的假设

### Requirement: 知识点路线图

规划师 MUST 生成一张包含先后依赖的知识点路线图，每个知识点 MUST 标注掌握状态与来源资料。

#### Scenario: 生成路线图

- **WHEN** 目标与澄清信息确认完成
- **THEN** 系统展示路线图，节点按前置依赖排序，未满足前置的知识点标记为"未解锁"

#### Scenario: 依赖关系展示

- **WHEN** 用户查看某个知识点
- **THEN** 系统显示它的前置知识点以及"学完前置才能开始"的提示

### Requirement: 每日任务生成

规划师 MUST 按当前阶段生成每日任务，每天 1 至 3 项，每项 MUST 标注对应知识点与预计用时。

#### Scenario: 查看今日任务

- **WHEN** 用户进入今日学习页
- **THEN** 系统列出当天 1 至 3 项任务，包含知识点名称与预计用时，总时长接近用户设定的每日时长

#### Scenario: 当天任务已完成

- **WHEN** 用户完成当天全部任务
- **THEN** 系统显示"今日已完成"，并提示下一天的首个任务，不提前解锁后续阶段

### Requirement: 单目标约束

系统 MUST 在任一时刻只维护一个进行中的学习目标；新建目标时 MUST 提示将归档当前目标。

#### Scenario: 新建第二个目标

- **WHEN** 用户已有进行中的目标时再次创建目标
- **THEN** 系统提示"当前目标将归档，已学记录保留"，并要求用户确认

### Requirement: 计划小调自动执行

系统 MUST 自动处理顺延与回炉两类小调整，不得要求用户逐次确认。

#### Scenario: 当天任务未完成

- **WHEN** 用户当天未完成某项任务
- **THEN** 系统在次日把该任务顺延，并保持路线图状态不变

#### Scenario: 抽查未通过

- **WHEN** 开场抽查未通过
- **THEN** 系统把对应知识点状态改为"待回炉"，并在当天任务中插入回炉任务

### Requirement: 计划大调需用户确认

规划师 MUST 以大调整方案的形式呈现阶段级变更，用户 MUST 点击确认后变更才生效。

#### Scenario: 进度严重落后

- **WHEN** 规划师判断当前进度落后超过既定阈值
- **THEN** 系统展示调整方案（如延长周期、减少每日新知识点），用户确认后才写入计划

#### Scenario: 用户拒绝调整

- **WHEN** 用户在大调确认框中点击"暂不调整"
- **THEN** 系统保持原计划不变，并记录本次拒绝，短期内不重复提出同一方案

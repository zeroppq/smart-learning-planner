# Spec Delta

## MODIFIED Requirements

### Requirement: 学习目标输入

系统 MUST 允许用户用一句自然语言描述学习目标，且 MUST 支持用户补充每天可用时长；修改每日时长 MUST 更新当前目标本身（同一目标记录、同一计划版本线），MUST NOT 归档当前目标另建新目标；修改后已有计划 MUST 保持可见；按新时长重新生成计划时版本 MUST 在原版本上递增，MUST NOT 回退；重新生成前系统 MUST 展示前后对比并由用户确认。

#### Scenario: 提交学习目标

- **WHEN** 用户输入"我想在三周内学懂大学计算机基础，为期末考试做准备"
- **THEN** 系统记录该目标，并把每天可用时长默认设为 40 分钟

#### Scenario: 修改每日时长

- **WHEN** 用户在目标设置中把每天可用时长改为 50 分钟
- **THEN** 系统更新当前目标的时长参数，当前计划保持可见，目标与计划版本线不变

#### Scenario: 修改时长后重新生成

- **WHEN** 用户确认按新时长重新生成计划
- **THEN** 新计划按 50 分钟排期，计划版本在原版本上递增（如 v1 变 v2），不回退为 v1

#### Scenario: 重新生成前的前后对比确认

- **WHEN** 用户修改每日时长并触发生成
- **THEN** 系统展示调整前后的对比（如每日任务数、总天数、每项预计用时），用户确认后才写入

### Requirement: 每日任务生成

规划师 MUST 按当前阶段生成每日任务，每天 1 至 3 项，每项 MUST 标注对应知识点与预计用时；每日任务的数量与安排 MUST 由每日时长参与推导，不同时长 MUST 产生可区分的任务安排；计划页 MUST 明示每日任务安排的决定因素（知识点数量、学习周期与每日时长）。

#### Scenario: 查看今日任务

- **WHEN** 用户进入今日学习页
- **THEN** 系统列出当天 1 至 3 项任务，包含知识点名称与预计用时，总时长接近用户设定的每日时长

#### Scenario: 时长影响任务安排

- **WHEN** 同一组知识点分别按每天 40 分钟与 50 分钟生成计划
- **THEN** 两份计划的每日任务安排可区分（每日任务数或总天数不同），而不是只有每项预计用时不同

#### Scenario: 任务安排决定因素明示

- **WHEN** 用户查看计划页的每日任务区
- **THEN** 页面明示每日任务安排由知识点数量、学习周期与每日时长共同决定

#### Scenario: 当天任务已完成

- **WHEN** 用户完成当天全部任务
- **THEN** 系统显示"今日已完成"，并提示下一天的首个任务，不提前解锁后续阶段

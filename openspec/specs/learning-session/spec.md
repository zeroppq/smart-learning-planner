# learning-session Specification

## Purpose
承载每天真正发生的学习过程：先抽查旧知识防止遗忘，再带学新知识点，最后用"讲清楚、做对题、做出来"三层判定学生是否真的掌握，并把结果交给计划与可视化。

## Requirements

### Requirement: 今日学习页引导

督学 MUST 在今日学习页按"抽查 → 带学 → 三层判定 → 记录"的顺序推进，不得只被动等待用户提问。

#### Scenario: 进入今日学习页

- **WHEN** 用户进入今日学习页且当天存在待办任务
- **THEN** 督学主动发起开场抽查，而不是只显示一个空白对话框

#### Scenario: 今日无待办任务

- **WHEN** 当天任务已全部完成
- **THEN** 督学展示今日完成摘要，并询问是否进行额外复习或答疑

### Requirement: 开场抽查

督学 MUST 按 1 / 3 / 7 天间隔挑选已学知识点进行抽查，且 MUST 支持用户手动触发一次抽查。

#### Scenario: 按间隔抽查

- **WHEN** 用户进入学习页且存在到期复习的知识点
- **THEN** 督学抽出 2 至 3 个问题，覆盖到期知识点

#### Scenario: 手动触发抽查

- **WHEN** 用户点击"现在就抽查我"
- **THEN** 督学立即从已学知识点中抽题，不等待到期时间

#### Scenario: 抽查未通过

- **WHEN** 用户对抽查问题回答错误或明显含糊
- **THEN** 督学判定该知识点未通过，并说明卡在哪一步

### Requirement: 带学讲解

督学 MUST 结合知识库原文讲解当前知识点，讲解内容 MUST 引用来源文档名与段落序号。

#### Scenario: 讲解新知识点

- **WHEN** 用户开始学习一个新知识点
- **THEN** 督学用通俗语言讲解核心概念，并标注所引用的资料段落

#### Scenario: 用户要求举例

- **WHEN** 用户在讲解过程中要求"举个例子"
- **THEN** 督学给出一个贴近课程内容的例子，仍标注引用来源

### Requirement: 三层判定之讲清楚

督学 MUST 要求用户用自己的话复述知识点，第一层的判定标准 MUST 与题面要求一一对应（说清是什么、解决什么问题、举一个例子），讲不清楚 MUST 判定为未通过。"与本章其他概念的关系" MUST NOT 作为第一层的判定标准或缺口，只能作为讲解或建议内容展示。

#### Scenario: 复述清楚

- **WHEN** 用户用自己的话说明概念是什么、解决什么问题并举出例子，但没有提及它与本章其他概念的关系
- **THEN** 督学判定"讲清楚"通过，进入"做对题"；"与本章的关系"作为建议展示，不影响结论

#### Scenario: 复述含糊

- **WHEN** 用户只是重复原文、缺少题面三要素中的任一项或答不出追问
- **THEN** 督学判定"讲清楚"未通过，指出缺口并要求重新复述

### Requirement: 三层判定之做对题

督学 MUST 出至少一道题并要求用户独立作答，答错或只能靠提示答对 MUST 判定为未通过。

#### Scenario: 独立答对

- **WHEN** 用户在不看资料的情况下答对题目
- **THEN** 督学判定"做对题"通过，并给出简要讲解

#### Scenario: 答错

- **WHEN** 用户答错
- **THEN** 督学指出错误原因并给出变式题，答对后仍记为"补考通过"

### Requirement: 三层判定之做出来

督学 MUST 给出一个应用型小任务，由用户提交文字答案或方案，督学 MUST 按事先展示的评分标准评阅并给出通过或不通过。

#### Scenario: 提交任务答案

- **WHEN** 用户提交文字答案
- **THEN** 督学按已展示的标准逐条评阅，给出通过与不通过的明确结论

#### Scenario: 答案不完整

- **WHEN** 用户答案缺少关键步骤
- **THEN** 督学指出缺失项，判定未通过，并允许用户修改后重新提交

### Requirement: 判定标准前置展示

督学 MUST 在开始三层判定前展示本知识点的过关标准，判定过程中 MUST NOT 擅自降低标准；判定 MUST 只依据当前层前置展示的标准，标准外的内容（包括讲解细节与其他层要求）MUST NOT 作为不通过理由，只能作为建议；缺口清单 MUST 逐条对应本层标准。

#### Scenario: 开始判定前

- **WHEN** 用户进入某个知识点的判定环节
- **THEN** 系统展示该知识点三层的过关标准

#### Scenario: 用户求放宽

- **WHEN** 用户表示"差不多就行"
- **THEN** 督学不降低标准，并说明未通过的具体原因

#### Scenario: 标准外内容不作为不通过理由

- **WHEN** 用户的回答覆盖了当前层全部标准，但缺少标准之外的内容（例如讲解中补充的机制细节）
- **THEN** 督学判定通过，标准外内容只能出现在建议里，不得出现在缺口清单中

### Requirement: 掌握状态记录

系统 MUST 为每个知识点记录三层各自的结果与整体掌握状态，状态取值 MUST 为 not_started、learning、passed、needs_review 之一。

#### Scenario: 三层全部通过

- **WHEN** 讲清楚、做对题、做出来三层均通过
- **THEN** 系统把该知识点状态设为 passed，并记录本次学习时间

#### Scenario: 任一层未通过

- **WHEN** 任意一层未通过
- **THEN** 系统把该知识点状态设为 needs_review，并记录未通过的具体层与原因

### Requirement: 重判一次

系统 MUST 允许用户对未通过结论申请重新判定一次，重判结论 MUST 为最终结果；申请重判 MUST NOT 要求用户重新填写回答，重判基于上一次提交的回答与补充说明进行；重判次数 MUST 在全部参数校验通过且重判完成后才扣除，校验失败或判定服务失败 MUST NOT 消耗重判机会。

#### Scenario: 申请重判

- **WHEN** 用户在判定未通过后填写补充说明并点击"申请重判"
- **THEN** 系统基于上一次提交的回答与补充说明重新判定，反馈就地显示在重判区块内，并明确告知本次为重判最终结果

#### Scenario: 重复申请

- **WHEN** 用户在同一知识点第二次申请重判
- **THEN** 系统拒绝并提示"该知识点重判机会已用完"

#### Scenario: 无效重判不扣次数

- **WHEN** 重判请求因补充说明过短、回答缺失或判定服务失败而未完成
- **THEN** 系统就地提示失败原因，该知识点的重判机会保持未使用

#### Scenario: 重判进行中

- **WHEN** 用户点击"申请重判"后请求尚未返回
- **THEN** 按钮显示进行中状态且不可重复点击，页面有可观察的反馈

### Requirement: 知识库答疑

系统 MUST 允许用户在学习过程中随时提问，回答 MUST 基于知识库并标注出处；无法在资料中找到依据时 MUST 明确说明，不得编造。

#### Scenario: 资料中有答案

- **WHEN** 用户提问且资料中存在相关内容
- **THEN** 系统给出回答并标注文档名与段落序号

#### Scenario: 资料中没有答案

- **WHEN** 用户提问但知识库中没有相关内容
- **THEN** 系统说明"当前资料未覆盖该问题"，并建议补充资料或换个问法

### Requirement: 判定反馈结构化展示

判定结果 MUST 以"结论徽章 + 达标项清单 + 缺口清单"的结构展示，缺口条目 MUST 高亮标识。

#### Scenario: 判定未通过

- **WHEN** 判定结论为未通过或部分通过
- **THEN** 页面显示结论徽章、已达标项清单与缺口清单，缺口条目高亮

#### Scenario: 判定通过

- **WHEN** 判定结论为通过
- **THEN** 页面显示结论徽章与达标项清单，不显示缺口区
